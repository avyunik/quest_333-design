# Codex Warm Redesign V3 — исходники и задания

Пакет предназначен для переноса в существующий репозиторий игры «Заправка 3:33».

## Состав
- `PROMPT_CODEX.md` — основная постановка задачи (аудит UX → дизайн-система → 28 реализованных экранов → ассеты → QA).
- `PROMPT_ASSET_EXPORT.md` — дополнительный промпт на окончательную подготовку самостоятельных ассетов после реализации экранов.
- `SCREENS.json` — 28 ID/названий/путей с сохранённым порядком из PDF.
- `inputs/pdf/` — исходные PDF с текстовыми описаниями на одном длинном листе.
- `inputs/host/` и `inputs/player/` — 13 + 15 автоматически извлечённых исходных скриншотов. Их порядок соответствует порядку описаний сверху вниз.
- `inputs/visual_references/` — 5 атмосферных примеров, переименованы для удобства Codex.

## Как использовать
1. Распакуй весь каталог в репозиторий под `design/redesign-warm-v3/` (чтобы относительные пути в задании совпадали).
2. В Codex, открытом **в корне репозитория**, отправь: `Прочитай design/redesign-warm-v3/PROMPT_CODEX.md и выполни это задание в указанном порядке. Используй SCREENS.json и все inputs. Не изменяй текущую V2.`
3. Проверяй результаты после пилотных экранов; на следующих запусках Codex проси продолжить по перечню из `SCREENS.json` и `docs/screen-matrix.md` без повторного исследования уже завершённых частей.
4. Когда V3 реализована, дай второй запрос: `Выполни design/redesign-warm-v3/PROMPT_ASSET_EXPORT.md на реализованной V3.`

**Важно:** исходные референсы — плоские UI-скриншоты. Кропнуть из них отдельную несуществующую чистую фоновую сцену без артефактов технически невозможно. Если генератор/редактор изображений Codex не подключён, чистые новые фоны и предметы надо сгенерировать отдельно и импортировать; Codex должен подготовить список этих зависимостей, а не притворяться, что они получены.

## Наблюдение при анализе PDF
Описание экрана входа ведущего в первом PDF ошибочно повторяет описание «Пролога» — см. `PROMPT_CODEX.md`, соответствующий экран является формой входа по коду ведущего.
