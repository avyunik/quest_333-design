# Подключение к основной платформе

## Границы

Frontend: `src/features/warm-redesign-v3/{app.js,style.css,index.html,catalog.json}`. App.js содержит нативные функции компонентов Shell, Panel, Shelf, Register, Book, формы, общий обработчик действий и canvas. UI не использует скриншоты или PDF как панели. Styling изолирован самим preview-маршрутом; при встраивании в общий DOM нужно ограничить CSS контейнером или Shadow DOM, поскольку текущий standalone CSS включает body/button/header.

`server.py` — заменяемый демонстрационный adapter. Стандартная библиотека Python, state в памяти, RLock для последовательных мутаций. Перезапуск теряет всё состояние. Секреты вынесены из клиентского JS, но код входа публичен для исследования дизайна. Перед production: реальная авторизация и проверка членства, CSRF/Origin, rate limits, постоянное хранилище, серверные события и контрактные тесты платформы. Не переносить preview-вход в production.

## Preview API (не навязанный контракт платформы)

- POST `/api/login`: role, name, team, player, code для ведущего; HttpOnly SameSite cookie.
- POST `/api/logout`: удаляет сессию.
- GET `/api/state`: общие episode/phase/deadline/paused, безопасная сводка teams и данные own. Host дополнительно получает ключи и обе полные команды. Player получает coordinate только после подтверждения роли; shelfSource только в memorize; riddle/privatePicture только активному. Polling 1500ms.
- GET `/api/picture`: SVG текущей личной ассоциации; 403 неактивному, no-store. На платформе заменить ссылками с проверкой доступа, не публичными предсказуемыми URL.
- POST `/api/action`: action, value, необязательные team/index/kind. Сервер проверяет role, владельца барабана, ход рычага и фазу полки. Ошибки JSON с HTTP 400/401/403.

События: role→confirm→clue/cell; phase(memorize/reconstruct)→shelf/discard/checkShelf; gauge/normalize/emergency; route/undoRoute/checkRoute; draw/answer(puzzle)→accept/reject; drum/pull/resetDrums; vote/resolve/round; episode/ready/hint/pause/extend/finish. focusTeam переключает исследуемую команду у ведущего. nextPlayer меняет активного в карте и рисунке.

Нужно заменить fixtures ITEMS/WORDS/LEVER_ACTIONS, текст памятки/загадки, ограничения подсказки, переходы и счётчики реальными конфигурациями. Рычаги сейчас меняют только собственную шкалу; сложная матрица влияний неизвестна. Новая очередь рисунков и набор будущих загадок требуют production-сценария. При смене активного рисунок сохраняется до явной очистки — для аудита состояния.

Таймер preview ограничивает только показ полки. Пауза и продление работают на серверном deadline; прочие этапы не блокируются по таймеру. Роли, попытки, голоса и порядок предметов не должны определяться локальным UI в интеграции. Сохранить фильтрацию DTO на сервере; CSS-скрытие недостаточно. Пять барабанов рассчитаны на пять мест. Распределение нескольких одному участнику возможно только после получения правил платформы.

## Медиа и ассеты

Заменить placeholder video/audio доверенными URL платформы; после видео подключить ended к разрешённому сервером переходу. UI не утверждает, что отсутствующий ролик воспроизведён. Настоящие результаты и памятное фото приходят с backend; текущая открытка — фон-иллюстрация станции. Локальный прямой каталог не должен обходить production-доступ.
